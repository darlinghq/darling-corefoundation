# NSInvocation and forwarding across calling conventions

`nsinvocation-abi.m` invokes methods through NSInvocation and through `forwardInvocation:` with narrow integers, floats, doubles, structs of 8, 16 and 40 bytes, a four-double aggregate and arguments that spill to the stack, and checks the results. The last check sends `forwardInvocation:` to `super` from a class whose `methodSignatureForSelector:` accepts the selector; the default implementation must raise `NSInvalidArgumentException` (it used to re-invoke the invocation on the target, which recursed until the stack overflowed). It prints `N/N passed`.

The register and stack rules it covers are the arm64 ones; on x86_64 the same cases pass before and after, apart from the `super` check. On arm64 the invoke trampolines used to read the return type as a pointer, so most cases crashed.

On arm64 a struct of more than 16 bytes that is not an aggregate of one to four doubles (24-byte and 40-byte structs, `long[3]` in a struct, five doubles) is passed as a pointer to a caller-made copy, in the next integer register or an 8-byte stack slot, and returned through the address in x8. The tests set and read such arguments by value and invoke and forward them, including a reference argument that lands in a stack slot. Aggregates of doubles hidden behind a `long double` member or an array member still travel in d registers, and a four-double aggregate that does not fit in the remaining d registers goes to the stack whole. The expected values were fixed by running the same cases on macOS. macOS reads a 24-byte struct argument from the wrong place when it follows nine double arguments, so that case is covered only by the host tests in `tests/nsinvocation-arm64-host/`, which run the extracted placement code and trampolines against compiled functions on an arm64 Mac.
