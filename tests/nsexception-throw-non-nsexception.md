# Throwing an object that is not an NSException

Build `nsexception-throw-non-nsexception.m` against Foundation/CoreFoundation (MRC, 64-bit; the exception preprocessor is not installed on i386) and run it under Darling. It throws a string, an instance of an `NSObject` subclass that is not an `NSException`, and an instance of a root class that implements `retain` and `release` (the throw retains and later releases the object) but not `isKindOfClass:`, and checks that each reaches its `@catch` as the very same object (the string through `@catch (NSString *)`). It also throws an `NSException` and an `NSException` subclass instance and checks that the caught object is the thrown one and that `callStackSymbols` is not empty and has as many `callStackReturnAddresses`, which is how the stack trace the exception preprocessor records is observed. Throwing `nil` is not tested. The test turns stdout buffering off, so every `FAIL` line printed before a crash is not lost when stdout is a pipe.

Installed baseline: the exception preprocessor sends `_installStackTraceKeyIfNeeded` to every thrown object, so the string and the `NSObject` subclass instance are not delivered to their handlers; the throw raises `NSInvalidArgumentException` (unrecognized selector) and that exception is caught by `@catch (id)` instead, or, for the string, is not caught by `@catch (NSString *)` at all, and the checks that compare the caught object with the thrown one fail. For the root class the forwarding machinery recurses and the process crashes (the object implements neither `_installStackTraceKeyIfNeeded` nor `methodSignatureForSelector:`, so each forward is forwarded again), so that case runs last; candidate: prints `PASS`. The `NSException` cases pass on both.

Not run under Darling by the author; checked with `clang -fsyntax-only` against stub headers only, see the commit message.
