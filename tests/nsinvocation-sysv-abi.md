# NSInvocation and forwarding on x86_64 and i386

`nsinvocation-sysv-abi.m` invokes methods through NSInvocation and through `-forwardInvocation:` and `-forwardingTargetForSelector:` with floating-point, long double, struct and stack arguments and results, laid out as the System V AMD64 ABI (x86_64) and the i386 cdecl convention pass them. It prints `N/N passed`. Build for `x86_64-apple-macos10.15` and `i386-apple-macos10.13` and run both under Darling.

Cases: int/float/double/long long mix; float, double and long double arguments and results; structs of 3 bytes, 8 bytes, 12 bytes (three floats), 16 bytes (two longs, two doubles, four floats, long plus double, double plus long), 24 bytes and 40 bytes (returned through a hidden pointer); eight integers of mixed widths and ten doubles (stack arguments); structs that no longer fit in the remaining registers and move to the stack whole; five double pairs; every result shape again through `-forwardInvocation:`, and a subset through `-forwardingTargetForSelector:` (which restarts the send, including `objc_msgSend_stret`).

On x86_64 the following fail without the change: all results of structs of 16 bytes or less (treated as hidden-pointer results), float, double and long double results of forwarded messages (the trampoline loaded them from beyond its frame and overwrote it for larger values), every forwarded message whose result is returned through a hidden pointer (the receiver was read from the wrong register), `-forwardingTargetForSelector:` redirection when the argument registers matter, stack arguments after a hidden pointer result (offset by one word), narrow integers on the stack (4-byte slots instead of 8), and structs split across integer and SSE registers. On i386 every `-invoke` dereferenced its return type character as a pointer, forwarded float, double and long double results were lost, forwarded hidden-pointer results read the selector as the receiver, and 8-byte struct results used the wrong convention.

Also covered: narrow integer arguments and results are widened to 32 bits for the callee, structs holding a single float or double (also nested or in a one-element array) come back in st(0) on i386, signature frame lengths on x86_64 (checked against macOS), and arguments split across registers read back through `-getArgument:atIndex:`. The whole guest test passes on macOS x86_64 (run under Rosetta); unions are not in it because NSMethodSignature on macOS rejects them.

`nsinvocation-sysv-host/run.sh` runs the placement and trampoline code of NSMethodSignature.m, NSInvoke-x86.S and CFForwardingPrep.S directly on a Linux x86_64 host against functions compiled by the host compiler, which uses the same ABI (invoke.c and forward.c: 34 and 15 cases). When the host can build 32-bit programs it also runs the i386 trampolines and result rules (invoke32.c and forward32.c, 22 and 14 cases; the compiler is run with `-freg-struct-return` so small structs come back in registers as on Darwin), which include unions, hidden-pointer structs and x87 results. It needs clang and python3.
