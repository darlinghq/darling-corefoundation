# CFStringTokenizer text lifetime

Build `cfstringtokenizer-text-lifetime.c` against CoreFoundation and run it under Darling. The tokenizer hands its UTF-16 text to an ICU break iterator, and the iterator keeps the pointer instead of copying the text. The test tokenizes with `kCFStringTokenizerUnitWordBoundary` (every word and every space, in order), but only after it overwrote the stack (a 64 KB array filled with UTF-16 `z`) and, for strings longer than 768 characters, reused the freed heap block (80 allocations of that size and its four neighbouring 16-byte sizes, filled with `z`). It covers a 30 character string, a 2000 character string, `CFStringTokenizerSetString` replacing the text with a longer and then a shorter one, an empty string and a one-character string, and releases every tokenizer.

Installed baseline: the text is copied to a stack array (up to 768 characters) or a malloc buffer that is gone when `CFStringTokenizerCreate` / `CFStringTokenizerSetString` return, so the short and long cases read the overwritten memory and return other ranges; candidate: zero failures. The stack overwrite in the short case is deterministic. The heap reuse in the long case is not guaranteed to reproduce on every malloc implementation, so a pass there is weaker evidence than a failure on the baseline. AddressSanitizer only reports the old reads if ICU itself is built with it (the reads happen inside ICU), so the test overwrites the memory instead of relying on a sanitizer; with an instrumented ICU, `-fsanitize=address` and `ASAN_OPTIONS=detect_stack_use_after_return=1` should flag the baseline as stack-use-after-return and heap-use-after-free. The test releases every tokenizer but does not check for leaks itself; run it under a leak checker for that.

## Paragraph unit

`kCFStringTokenizerUnitParagraph` must split at paragraph separators, not at sentence ends. The test checks that `"A. B.\nC."` is two paragraphs (`{0,6}` and `{6,2}`; the sentence iterator gives three), that CR LF, CR, LF and U+2029 end a paragraph while U+0085 and U+2028 do not (the separator set of `CFStringGetParagraphBounds`), an empty line, text without a separator, the empty string, and that `CFStringTokenizerSetString` keeps the unit.

Installed baseline: the paragraph unit uses the sentence break iterator, so `"A. B.\nC."` returns three tokens instead of two; candidate: zero failures.
